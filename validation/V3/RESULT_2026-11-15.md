## Defect found when looking into mark 2: the V3 run did not use the two V3 features

The `.command.sh` of RESISTOME_TABLES shows `... core 0.90 0.95 0.8 4 0.85`. The module (`modules/local/resistome_tables/main.nf`, commit 93eb4e8)
declares `core_min_reads` before `probable_gene_identity`, but `workflows/seq_resistome.nf` passes them in the opposite order. So the script got
probable-homolog identity = 4 (class never fires: 0 probable homologs) and core minimum reads = 0.85 (so the effective minimum stayed at min_arg_reads = 2).
The unit tests call the script directly, so they did not see it; the `-profile test` checks did not exercise either value.
Consequence: this run tested the V2 rule plus the loose-ortholog explanation, not the pre-registered V3 pipeline. The 9 unexplained calls are all
"high_identity" route calls with 2-4 reads (QnrB32 x4, MdtK x2, emrB, OmpK37, acrA 7 reads, mdtF 2 reads); a 4-read minimum would have removed
most of them. This is analysis only; no fix, no rerun made.
